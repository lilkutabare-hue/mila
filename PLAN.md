## Контекст

Сайт статический, `docs/` раздаёт GitHub Pages. Его же встраивает Тильда блоком T123: разметка для встраивания лежит в `docs/assets/js/markup.js` и должна совпадать с `docs/index.html`.

Что есть сейчас:
- **Лента** (`strip.js`, layout `scatter`): бесконечный горизонтальный коллаж, на телефоне одна ось (`layoutTight`), на десктопе колонки.
- **Сверху** `modeling / styling` (`.roles`): фильтр. Подчёркивание рисуется слева, второе слово приглушено. Смена фильтра — `strip.swap()`: карточки уходят с поворотом и блюром и садятся новые.
- **Снизу** `contact / wardrobe` (`.nav`): активное слово проявляется из блюра, по нему бежит блик (`@keyframes glint`).
- **Съёмка**: `.layer.project` с лентой-бэндом, фон ленты блюрится (`body.project-open #stage{filter:blur(14px)}`).
- **Wardrobe**: justified-ряды, ленивая загрузка (`wardrobe.js`). Сверху и снизу бумажные градиенты под навигацией: `body.wardrobe-open .roles` и `body.wardrobe-open .nav` в `style.css`.
- **Viewer**: один кадр, HQ поверх. В нём уже есть FLIP-путь `fromRect`, но работает только для `source: 'rail'`, а main.js всегда передаёт `'wardrobe'` и `railRectOf: () => null`. Сейчас этот путь спит.

Стиль, который не трогаем: бумага `#F2F0EB`, Helvetica Neue, всё строчными, навигация 11px с `mix-blend-mode: difference`, кривая `cubic-bezier(.2,.7,.1,1)`.

Аудитория: ссылка из био Instagram, то есть телефон и встроенный браузер Instagram или Telegram. Цель — **60 fps на iPhone 12 во встроенном браузере**.

## Принцип

«Дорого» = меньше движений, но каждое точное и одного почерка. Правила:
1. Одна система движения: три кривые, три длительности (этап C1). Никаких своих чисел в отдельных местах.
2. Анимация только на смену состояния. В покое ничего не шевелится, кроме блика на активном слове, и тот редко.
3. Кадр никогда не появляется пустой рамкой: сначала цвет или плейсхолдер, потом фото.
4. `prefers-reduced-motion` → мгновенные смены, как сейчас.

## Этап A — убрать лаги

**A1. Лента спит, когда стоит.** `strip.js` `frame()` перезапрашивает `requestAnimationFrame` всегда, а `tick()` каждый кадр пишет `track.style.transform` и обходит все узлы, даже без движения.
- Сделать: когда `pos === target`, `dragY === dragYTarget`, `inVel === 0` и ни одна картинка не грузится (`pending === 0`, фоновая предзагрузка закончилась), не перезапрашивать rAF.
- Будить через `run()` на `wheel`, `pointerdown/move`, `keydown`, resize, `visibilitychange`, в `swap()` и в `setItems()`. Проверку размеров раз в ~⅓ секунды (`sizeCheck`) убрать: её закрывают ResizeObserver и resize.
- Готово, когда: в Performance-записи 5 секунд покоя — ноль кадров от страницы.

**A2. Видео-тизеры.** Сейчас в ленте играет каждое видео, видимое на 30% и больше.
- Сделать: на телефоне играет одно видео — самое видимое, на десктопе максимум два. Остальные на паузе, на постере.

**A3. Wardrobe.** 205 плиток в одном скролле.
- Сделать: `.section{content-visibility:auto; contain-intrinsic-size:auto 600px}`, чтобы браузер не рисовал съёмки за экраном.
- Плитке ставить `.loaded` только после `img.decode()`, а не по `onload`: декодирование не попадёт в кадр скролла.

**A4. Блюр всего экрана.** `filter: blur(14px)` на `#stage` с десятком фото — самая дорогая операция на сайте, и она анимируется 0.5 с.
- Сделать: сначала замерить на iPhone, открывая и закрывая съёмку и contact. Если кадры падают — блюр 8px вместо 14px и `will-change: filter` только на время перехода. Если и так падают — переход только прозрачностью, блюр включать после него.

**A5. Пустые рамки.**
- Сделать: в `tools/build-media.mjs` считать средний цвет каждой работы (`sharp(...).stats()` → `dominant`) и класть в манифест полем `color: '#rrggbb'`. В ленте, бэнде, wardrobe и viewer это фон рамки, пока фото не загрузилось: вместо серого `--ghost` рамка сразу «в цвет» кадра.
- Только для витрины (см. «Отдельно» ниже) дополнительно крошечный плейсхолдер 12px по ширине, base64 webp, поле `ph`. Гзип манифеста сейчас ~10 KB, плейсхолдеры не должны добавить больше ~15 KB.

## Этап B — плашки в wardrobe

Сейчас это не блюр, а бумажный градиент с жёсткой точкой `var(--paper) 62%` (style.css, строки с `body.wardrobe-open .roles` и `body.wardrobe-open .nav`). На 62% получается видимая кромка, поэтому читается как «плашка».

**Сделать (основной вариант): мягкая вуаль без кромки.**
- Градиент на 8–10 точек по кривой ease-out: непрозрачность 1 → .97 → .9 → .78 → .6 → .4 → .22 → .08 → 0. Цвет везде бумажный.
- Высота: сверху 56px + safe-area, снизу 72px + safe-area.
- Готово, когда: на скриншотах wardrobe поверх тёмного и светлого кадра нет различимой линии.

**Вариант на пробу:** «прогрессивный блюр», как в iOS 26/27. Три-четыре слоя `backdrop-filter: blur(2/4/8/16px)`, каждый со своей `mask-image` полосой, сверху тонкая бумажная вуаль.
- Оставить, только если на iPhone при скролле wardrobe держится 60 fps. Иначе остаётся основной вариант.

## Этап C — движение

**C1. Токены движения.** В `:root`:
- `--e-out: cubic-bezier(.2,.7,.1,1)`, `--e-io: cubic-bezier(.7,0,.2,1)`;
- `--t-1: 180ms`, `--t-2: 360ms`, `--t-3: 600ms`.

То же константами в `media.js` для WAAPI. Все существующие переходы и анимации перевести на них. Визуально почти ничего не меняется, но всё начинает «дышать» одинаково.

**C2. Общий кадр: лента → съёмка.** Главный дорогой момент.
- Тап по кадру в ленте: этот кадр перелетает из своего места на своё место в бэнде съёмки. Остальные кадры бэнда садятся тем же движением, что новые карточки в `swap()` (поворот плюс блюр), с шагом 40–60 мс.
- Закрытие: обратно, если кадр ещё на экране ленты, иначе просто растворение.
- Реализация: View Transitions API (`document.startViewTransition`, Safari 18+ / Chrome 111+), `view-transition-name` только на тапнутом кадре. Где API нет — FLIP через WAAPI: rect «до» → rect «после», `transform`.
- То же для wardrobe → viewer. В viewer уже есть путь `fromRect`: обобщить с `source === 'rail'` на любой источник, `railRectOf` заменить на функцию, которая отдаёт rect плитки.
- Готово, когда: на видео экрана с iPhone кадр летит без рывка и без мигания.

**C3. Появление фото.** Один класс на всё: лента, бэнд, wardrobe, HQ во viewer.
- `opacity 0 → 1` и `filter: blur(6px) → 0` за `--t-2`. Поверх фона-цвета из A5 это выглядит как «проявка».
- Сейчас там просто `opacity .3s`.

**C4. Слои.**
- Wardrobe сейчас целиком выезжает снизу за 0.36 с. Заменить на «оседание»: `translateY(24px)` + `opacity 0` → на место за `--t-3`, ряды съёмок первого экрана с шагом 50 мс.
- Contact: строки (имя, instagram, telegram, почта) проявляются из блюра с шагом 40 мс.

**C5. Блик реже.**
- Сейчас `glint` крутится каждые 2.8 с. Сделать: один проход при активации, потом раз в ~7 с. Блик заметнее, когда редкий.
- Прелоадер (`boot.js`, имя пульсирует прозрачностью) перевести на тот же блик, чтобы у сайта был один почерк.

**C6. Тактильность.**
- `pointerdown` на кадре или плитке: `scale(.985)` за 120 мс, на `pointerup` обратно. Не срабатывает, если это начало драга, а не тап.

**C7. Только десктоп, по желанию.**
- Над кадром ленты за курсором плывёт подпись съёмки: 11px, `difference`, с мягким запаздыванием. Исчезает, когда курсор уходит с кадра.
- Перед этим показать Леше скриншот, это решение вкуса.

## Отдельно, когда Мила пришлёт файлы: витрина

Мила пометит в исходниках восклицательным знаком кадры для главной ленты. Сделать, только когда файлы будут в `media-src`:
- Сборка: файл с `!` в имени получает `showcase: true` в манифесте. `id` строится из хеша содержимого, поэтому переименование его не меняет.
- Ключи в `meta.json` — имена файлов. После переименования у файла с `!` появится новая запись, и его `role`, `caption`, `hide` потеряются. Сопоставлять запись по имени без `!` и переносить поля, старую запись удалить.
- Лента без выбранного фильтра показывает только витрину. С `modeling` или `styling` всё как сейчас.
- В `main.js` `pick()` есть запасной ход «если у роли нет кадров на рейле — берём все». Для витрины его не применять.
- Порядок витрины (фиксированный или перемешивать при каждом заходе) уточнить у Леши до реализации.
