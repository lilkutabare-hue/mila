## Контекст

Сайт-портфолио Милы (Instagram **@milaharys**): стилист, арт-директор, модель. Основной трафик — ссылка из био Instagram: телефон, встроенный браузер Instagram или Telegram. Поэтому **mobile-first**; десктоп — полноценная вторая версия.

Вдохновение — genevalukina.com: только медиа, белый воздух, порядок меняется при каждом заходе. Код пишем с нуля, идея своя: вместо вертикальной ленты — бесконечный горизонтальный **рейл**.

## Концепция: рейл

Весь сайт — штанга с одеждой в шоуруме стилиста.

- Через весь экран идёт тонкая линия — **рейл**. На ней на тонких **плечиках** висят фото и видео. Верх у всех на одной линии, длина разная, как у вещей на штанге.
- Скролл, драг и свайп = толкаешь вещи по штанге. Вещи **качаются**: низ отстаёт от движения, после остановки 2–3 затухающих колебания — и вещь **оседает**. Это главная фишка сайта.
- Проекты отделены друг от друга **разделителями** — узкими карточками на штанге, как разделители размеров в магазине; на карточке вертикально написано название проекта.
- На рейле висит **выборка**: до 6 работ из каждого проекта. Проекты идут в случайном порядке при каждом заходе, внутри проекта порядок сохраняется.
- Наведение (десктоп): вещь «берёшь в руку» — она перестаёт качаться, чуть приподнимается, рядом на нитке появляется **бирка**: номер, проект, категория, кредиты.
- Клик: вещь **снимается с вешалки** — фото перелетает из рейла в полноэкранный **вьюер** в высоком качестве, на штанге остаются пустые плечики. Закрыл — вещь возвращается на место.
- Кнопка **wardrobe** (аналог «Full Gallery»): все работы целиком, по проектам, обычный вертикальный скролл, всё в высоком качестве.
- Кнопка **contact**: имя, роль, контакты.
- Внизу счётчик и название текущего проекта: `014 / 090 · FOR HARRY DENIMS`.

## Жёсткие рамки

- Ванильный HTML/CSS/JS на ES modules, без фреймворков и сборщиков. Шрифты — только Google Fonts. Обработка медиа — Node-скрипт.
- Все медиа берутся из `media-src/`. Чужие фото, включая фото с genevalukina.com, в проект не попадают.
- **Исходники только читаются.** Единственное действие с ними — разовый перенос трёх папок в `media-src/` в фазе 0. Скрипт ничего в `media-src/` не переименовывает, не правит и не удаляет; дубли и пустые папки он пропускает и называет в отчёте.
- Результат — папка `public/`, готовая к загрузке на любой статический хостинг. Деплой делает пользователь.
- Не хватает данных (контакты, кредиты, город) — ставь `TODO` в `content/site.json` или `content/meta.json` и иди дальше. Все TODO перечисли в финальном отчёте.
- На референсном сайте нашлись ошибки, здесь их решаем сразу:
  1. Имена выходных файлов задаёт скрипт: только `[a-z0-9-]`, нижний регистр.
  2. Навигация всегда стоит на сплошном фоне с контрастом ≥ 4.5:1, фото под неё не заезжают.
  3. У медиа два **тира**: лёгкий `rail` для рейла и HQ `full` — только по запросу (wardrobe, вьюер).
  4. Есть og:image.
  5. Зум страницы разрешён: viewport — ровно `width=device-width, initial-scale=1`.
- Проверяй визуально сам во встроенном браузере (превью через `.claude/launch.json`): скриншоты десктопа 1440×900 и мобайла 390×844 после каждой фазы, начиная со второй.

## Фаза 1 — медиа-пайплайн `tools/build-media.mjs`

**Вход:** `media-src/<категория>/<проект>/файлы`, форматы `jpg jpeg png webp heic heif mov mp4 m4v`.
- Категория — папка первого уровня. Проект — папка второго уровня.
- Файл, лежащий прямо в папке категории, становится отдельным проектом; название берётся из имени файла без расширения.
- Пустая папка проекта пропускается и попадает в отчёт.
- Точные дубли (одинаковый хеш содержимого) внутри проекта: остаётся первый по имени, остальные попадают в отчёт.
- Порядок работ внутри проекта — натуральная сортировка имён файлов.
- Live Photo с iPhone — пара файлов с одинаковым именем (`IMG_1234.HEIC` + `IMG_1234.MOV`) — становится одним элементом типа `motion`, фото служит постером.

**Названия и ID:**
- Название проекта = имя папки, обрезанное по краям; фрагмент в подчёркиваниях `_Goodbuy horses_` превращается в кавычки «“Goodbuy horses”». Опечатки в названиях скрипт не исправляет — их правит пользователь в `meta.json`.
- `project.slug` — из названия: нижний регистр, кириллица транслитерируется, остаётся `[a-z0-9-]`.
- `item.id = <project.slug>-<первые 6 символов хеша содержимого>`. Такой ID не зависит от имени файла и порядка, поэтому ссылки на конкретную работу живут долго.

**Тиры:**

| | фото (sharp → webp) | видео (ffmpeg → mp4 H.264) |
|---|---|---|
| `rail` | высота 1200px, q78 | **тизер**: 12 с от `teaserStart` (по умолчанию 0), высота 720, ≤30 fps, crf 28, preset slow, без звука |
| `full` | длинная сторона 2560px, q86 | весь ролик, короткая сторона 1080, crf 22, `-maxrate 6M -bufsize 12M`, AAC 128k |
| `poster` | — | кадр на `teaserStart + 0.3` с → webp в размерах обоих тиров |

- Увеличения нет ни в одном тире: исходник меньше целевого размера остаётся в своём размере.
- Ориентация берётся из EXIF, включая зеркальные значения (`sharp().rotate()`); у ffmpeg — автоповорот. HEIC сначала конвертируется через `sips` во временный JPEG.
- У всех mp4 `-movflags +faststart` и `-pix_fmt yuv420p`.
- **Метаданные вычищаются полностью**: в выходных файлах нет EXIF и GPS.
- Бюджеты (превышение → предупреждение в отчёте): rail-фото в среднем ≤ 220 KB, rail-тизер ≤ 2.5 MB, full-фото ≤ 900 KB, full-видео ≤ 0.6 MB на секунду.
- Инкрементальность: если выход новее исходника, файл не перегенерируется. Выходы, у которых исчез исходник, удаляются (только внутри `public/media/`).

**`content/meta.json`** — то, что правит человек. Скрипт дописывает заготовки для новых проектов и файлов, существующие записи не трогает:
```json
{
  "projects": {
    "styling/For Harry Denims": { "title": "For Harry Denims", "credits": "", "order": null, "railCount": null }
  },
  "items": {
    "styling/For Harry Denims/IMG_3545.JPG": { "caption": "", "hide": false, "teaserStart": 0 }
  }
}
```
`order` — номер позиции проекта (1, 2, 3…), такие проекты стоят первыми; `null` — участвует в перемешивании. `railCount` — сколько работ проекта попадает на рейл (`null` → `railPerProject` из site.json). `hide: true` убирает работу с сайта.

**`public/data/manifest.json`:**
```json
{
  "generated": "…",
  "projects": [ { "slug": "for-harry-denims", "title": "For Harry Denims", "category": "styling",
                  "credits": "", "order": null, "items": ["for-harry-denims-a3f9c1", "…"] } ],
  "items": [ {
      "id": "for-harry-denims-a3f9c1", "project": "for-harry-denims", "type": "photo|motion",
      "onRail": true, "w": 2560, "h": 1441,
      "rail": { "src": "media/rail/for-harry-denims-a3f9c1.webp?v=a3f9c1", "w": 2132, "h": 1200 },
      "full": { "src": "media/full/for-harry-denims-a3f9c1.webp?v=a3f9c1", "w": 2560, "h": 1441 },
      "poster": { "rail": "…", "full": "…" }, "duration": 45.8, "hasAudio": true,
      "caption": ""
  } ]
}
```
`onRail` — первые `railCount` работ проекта. `?v=` сбрасывает кеш хостинга при замене файла.

**Дополнительно:** из первых кадров пяти проектов генерируются `public/og.jpg` (коллаж 1200×630) и монограмма `mh` в `favicon.png` (64) и `apple-touch-icon.png` (180).

**Отчёт в конце:** проекты и число работ в каждом; вес каждого тира; пропущенные дубли и пустые папки; исходники с длинной стороной меньше 1600px (в HQ будут мягкими); превышения бюджетов.

**Готово, когда:**
- `npm run media` на текущем материале даёт 17 проектов и 130 элементов (128 photo, 2 motion), в отчёте названы 2 дубля и пустая папка `For LAST SEEN`.
- Каждый файл, на который ссылается манифест, существует; все имена совпадают с `^[a-z0-9-]+\.(webp|mp4)$`.
- `sharp().metadata()` у выходных фото не содержит `exif`.
- Работы проекта `For Sorocolita` в выходных файлах стоят вертикально (в исходниках ориентация только в EXIF).
- Повторный запуск занимает секунды; содержимое `media-src/` не изменилось.

## Фаза 2 — рейл: движок

Собственный движок прокрутки на rAF. Натив-скролл здесь не используется: колесо мыши вертикальное, а рейл должен быть бесконечным без телепортаций.

**Что висит на рейле.** Элементы с `onRail: true`. В режиме `projects`: проекты с `order` идут первыми по номеру, остальные перемешиваются при каждом визите; перед каждым проектом стоит разделитель; внутри проекта порядок из манифеста. В режиме `mix`: все элементы выборки перемешаны, разделителей нет.

**Раскладка:**

| | линия рейла | плечики | высота вещи `H` | gap |
|---|---|---|---|---|
| десктоп ≥ 900px | `top: 18dvh` | 34px | `clamp(260px, 54dvh, 760px) × s` | `clamp(28px, 3vw, 56px)` |
| телефон, портрет | `top: 22dvh` | 24px | `50dvh × s` | 18px |
| телефон, альбом | `top: 12dvh` | 20px | `64dvh × s` | 16px |

`s` — случайный множитель 0.90–1.06 на каждый элемент и визит. Ширина считается из пропорций манифеста; максимум 82vw (у слишком широкого элемента уменьшается высота — на телефоне альбомные кадры висят короче портретных, это нормально). До загрузки на месте вещи стоит плашка `--ghost` точного размера. После загрузки — fade-in 300 мс.

**Бесконечность.** Каждый элемент (вещь или разделитель) получает `base.x` — накопленную позицию. `loopW` — длина круга, `pad = maxItemW + gap`. Пока `loopW < 1.5 × (vw + 2·pad)`, список повторяется; у дублей `aria-hidden="true"` и `tabindex="-1"`. Каждый кадр:

```js
const x = ((base.x - pos) % loopW + loopW) % loopW - pad;
```

Элемент вне `[-pad, vw + pad]` получает класс `.off` (`visibility: hidden`), его трансформ не пишется. Стартовая позиция: `pos = -(leftMargin + pad)`, первый разделитель у левого поля.

**Позиция:** `pos` плавно догоняет `target`, независимо от частоты кадров:
```js
pos += (target - pos) * (1 - Math.pow(1 - 0.12, dt / 16.67));
```
Скорость рейла `vel` (px/s) и ускорение `acc` (px/s²) считаются из `pos` и сглаживаются EMA. Они нужны физике в фазе 3.

**Ввод:**
- Колесо и трекпад (`passive: false` + `preventDefault`): `delta = |dx| > |dy| ? dx : dy`; при `deltaMode` 1 умножаем на 16, при 2 — на `vw`; `target += delta`.
- Pointer events с capture. Мышь двигает рейл только по X. Палец и перо двигают по доминирующей оси, свайп вверх = вперёд. При отпускании скорость считается по сэмплам за последние 100 мс, и `target += v × 0.35`. Сдвиг больше 6px считается драгом — клик после него гасится.
- Клавиатура: ← и → центрируют предыдущую или следующую вещь, PageUp/PageDown/Space сдвигают на 0.8·vw, Home возвращает к началу.
- На сцене `touch-action: none`; у html/body `overflow: hidden` и `overscroll-behavior: none` (жесты встроенного браузера Instagram не должны перехватываться).

**Загрузка:**
- `src` назначается, когда элемент попадает в окно `[-vw, 2·vw]`. Первые 4 вещи получают `fetchpriority="high"`, у всех изображений `decoding="async"`.
- Видео на рейле — тизер rail-тира с атрибутами в разметке `muted playsinline loop preload="none" poster`. Воспроизведение идёт, пока на экране видно ≥ 30% элемента.

**Счётчик и подсказка:** счётчик показывает номер вещи, ближайшей к центру экрана, среди вещей рейла (разделители не считаются) и название её проекта: `014 / 090 · FOR HARRY DENIMS`. На телефоне название проекта уходит на вторую строку. Подсказка `← drag · scroll →` гаснет после первых 200px движения.

**Ресайз:** debounce 150 мс; размеры пересчитываются, а вещь, стоявшая по центру, остаётся по центру.

**Доступность:** каждая вещь — `<button class="look" aria-label="014 — For Harry Denims, styling">`; при фокусе рейл центрирует её.

**Готово, когда:**
- Колесом, трекпадом, драгом мышью и свайпом (мобильная эмуляция) рейл проходит 3 полных круга в обе стороны без швов, прыжков и пустых дыр.
- Средний fps ≥ 55 за 5 с скриптованной прокрутки (замер через rAF).
- Первая загрузка весит ≤ 2.5 MB (Performance API, transferSize).
- Счётчик и название проекта меняются точно на границе проектов.

## Фаза 3 — рейл: физика, плечики, разделитель, бирка

**Плечики:** inline SVG внутри `.hang`. Крючок — маленькая дуга над линией рейла; от основания крючка две линии 1px `--ink` идут к верхним углам фото с отступом 8% от краёв. Вместе с верхним краем фото получается треугольник плечиков.

**Качание:** `.look` получает только `translate3d`, а `.hang` — только `rotate`, с `transform-origin: 50% calc(-1 * var(--hanger-h))`, то есть точка вращения в крючке. Состояние каждой вещи — угол θ (в градусах) и угловая скорость ω:

```js
const k = 38 * jitter;                    // jitter 0.85–1.15 у каждой вещи: качаются вразнобой
const c = 2 * 0.3 * Math.sqrt(k);         // ζ ≈ 0.3 — недодемпфировано
const wide = Math.min(1, h / w);          // альбомные кадры качаются слабее
const drive = -(acc * A + vel * V) * wide; // стартовые значения A = 0.006, V = 0.07
ω += (drive - k * θ - c * ω) * dt;        // dt в секундах, не больше 1/30
θ = clamp(θ + ω * dt, -7 * wide, 7 * wide);
```

Низ вещи **отстаёт** от движения рейла. Направление проверь глазами, при ошибке поменяй знак. Подбери A и V под цели из критерия ниже. Множитель `wide` нужен, потому что в материале много широких кадров 3:2: без него их углы улетают в соседей.

- **Разделитель:** узкая карточка `--tag` с обводкой, висит на рейле через прорезь вверху. Ширина 40px (32px на телефоне), высота — по тексту, но не больше 70% от `H`. Текст вертикальный (`writing-mode: vertical-rl`): название проекта, ниже мелко категория и число работ в проекте. Длинное название переносится во вторую колонку. Качается легче вещей: k ×1.6, `drive` ×1.3. Это `<button>` — открывает `#/wardrobe/<project.slug>`.
- **Ветерок:** когда рейл стоит дольше 1.5 с, к `drive` добавляется `B·sin(2πt/T + φ)`: T от 5 до 8 с, φ случайная, амплитуда ≈ 0.3°. Ветерок останавливается при первом движении.
- **В руке** (hover на устройствах `pointer: fine`): k ×4, ζ → 0.9, `translateY(-6px) scale(1.015)`, курсор `pointer`. На остальной сцене курсор `grab`, при драге — `grabbing`.
- **Бирка** (только при наведении): карточка `--tag` с дыркой-люверсом, висит на нитке 1px от крючка сбоку от верхнего угла фото и сама слегка покачивается. Внутри: `№ 014`, название проекта, категория, `credits`, у видео — `motion · 0:46`. Пустые поля скрываются. На тач-устройствах та же информация показывается во вьюере.
- **`prefers-reduced-motion: reduce`:** качания и ветерка нет (θ ≡ 0), коэффициент лерпа 0.35.

**Готово, когда:**
- Резкий флик даёт пик 4–7° у портретной вещи; после остановки видно 2–3 колебания, и вещь оседает (|θ| < 0.2°) за 1.2–1.8 с.
- Соседние вещи качаются заметно вразнобой; широкие кадры при флике не перекрывают соседей больше чем на треть gap.
- Клик по разделителю открывает wardrobe на нужном проекте (после фазы 4).
- При reduced-motion θ = 0 всегда; fps по-прежнему ≥ 55.

## Фаза 4 — wardrobe

- Слой во весь экран на фоне `--paper` со своим вертикальным скроллом (`overscroll-behavior: contain`), выезжает снизу за 360 мс. Пока слой открыт, рейл на паузе: rAF остановлен, видео стоят. Кнопка в nav меняет текст на `close`.
- Липкая шапка с фильтрами по категориям и счётчиками: `all 130 · styling 81 · modeling 38 · art direction + styling 11` (числа считаются из манифеста).
- Под шапкой **оглавление**: названия всех проектов строкой с переносами; клик плавно скроллит к секции проекта.
- **Секция проекта:** строка-заголовок (название · категория · число работ · кредиты), под ней все работы проекта, включая те, которых нет на рейле. Порядок проектов тот же, что на рейле в этом визите.
- Раскладка работ — **justified rows** по пропорциям из манифеста: целевая высота ряда 320px на десктопе и 180px на телефоне, gap 8px; последний ряд секции не растягивается.
- **HQ по правилу** `pickTier(item, cssW, cssH)`: если `cssH × devicePixelRatio ≤ rail.h × 1.05`, берём `rail`, иначе `full`. Так плитка всегда получает исходник не меньше своих физических пикселей. То же правило работает во вьюере.
- Ленивая подгрузка через IntersectionObserver с `rootMargin: 600px`. Видео-плитки показывают тизер, когда видно ≥ 50%.
- По клику открывается вьюер; «вперёд/назад» в нём идёт по всем работам текущего фильтра, через границы проектов.
- Маршруты: `#/wardrobe` и `#/wardrobe/<project.slug>` (открывает слой и скроллит к секции).

**Готово, когда:** в wardrobe видны все 130 работ в 17 секциях; сетка ровная на ширинах 375, 768, 1440 и 1920; фильтры и оглавление работают; на retina-экране крупные плитки грузят `full` (видно в Network); кнопка «Назад» и Esc закрывают слой.

## Фаза 5 — вьюер

- `role="dialog"`, `aria-modal`, фокус-ловушка. Управление: Esc, ← и →, горизонтальный свайп (50px или достаточная скорость), свайп вниз закрывает вьюер на телефоне.
- Медиа вписывается в экран с полями 48px на десктопе и 12px на телефоне.
- **Фото без вспышки:** сразу показывается rail-тир, уже лежащий в кеше, растянутым. Затем грузится `full` и подменяет его после `img.decode()`. Заодно предзагружаются `full` соседних элементов.
- **Видео:** full-тир, весь ролик. Стартует без звука с постера (`muted playsinline`). Свои минимальные контролы на стандартном video API: тап по видео — пауза/пуск; тонкая линия прогресса, по которой можно перематывать; время `0:12 / 0:46`; кнопка `sound on/off`. При уходе на соседний элемент видео останавливается.
- Под медиа — строка бирки: `№ 014 · название проекта · категория · credits`. Рядом `view project` → `#/wardrobe/<project.slug>` и `copy link` → копирует `…/#/look/<id>`, чтобы Мила могла отправить клиенту конкретную работу.
- **Снимается с вешалки** (открытие с рейла): FLIP от прямоугольника фото на рейле к прямоугольнику во вьюере, 420 мс, `cubic-bezier(.2,.7,.1,1)`. Пока вьюер открыт, фото на рейле скрыто, а плечики остаются видимыми. При закрытии анимация идёт обратно в текущую позицию вещи. При открытии из wardrobe — простой fade+scale. При reduced-motion — кроссфейд 150 мс.

**Готово, когда:** при открытии нет белых вспышек; ссылка `#/look/<id>` открывает вьюер сразу при загрузке страницы, в том числе для работы, которой нет на рейле; FLIP возвращает вещь точно на её место; оба видео проигрываются целиком, звук включается кнопкой, перемотка работает.
