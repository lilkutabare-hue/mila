# Портфолио mila harys — как пользоваться

Сайт — статический: папка `docs/` целиком заливается на любой хостинг (Netlify, Vercel, GitHub Pages, обычный FTP). Ничего собирать на хостинге не нужно.

## Где живёт сайт

- Код и медиа: репозиторий `github.com/milaharys/web`, папка `docs/` раздаётся через GitHub Pages на домене `https://milaharys.com` (файл `docs/CNAME`).
- Тильда больше не нужна: сайт живёт на своём домене. Блок `tilda/T123.html` оставлен на случай встраивания куда-то ещё.
- Обновить сайт: `npm run media`, затем `git add -A && git commit -m "…" && git push`. Через минуту-две GitHub Pages отдаёт новое. Тильда ничего не кеширует, потому что файлы грузятся не с неё.
- На машине без `media-src/` (правки только кода) `npm run media` медиа не трогает и лишь штампует новую версию кода, чтобы кеши обновились.

## Быстрый старт

```bash
npm install        # один раз
npm run media      # обработать фото и видео → docs/
npm run dev        # посмотреть локально: http://localhost:5173
```

После `npm run media` залейте содержимое `docs/` на хостинг.

## Добавить проект

1. Создайте папку `media-src/<категория>/<Название проекта>/` и положите в неё файлы (JPG, JPEG, PNG, WEBP, HEIC, MOV, MP4).
   Категория — одна из папок первого уровня: `styling`, `modeling`, `artdir + styling`. Новую категорию можно просто создать папкой, а её отображаемое название вписать в `content/site.json` → `categories`.
2. `npm run media`. Скрипт:
   - сам сделает лёгкие версии для рейла и HQ-версии для gallery и вьюера, вычистит EXIF и GPS;
   - пропустит точные дубли и пустые папки и назовёт их в отчёте;
   - допишет заготовки для новых проектов и файлов в `content/meta.json` (существующие записи не трогает);
   - повторный запуск занимает секунды — пересчитываются только новые или изменённые файлы.
3. Залейте `docs/`.

Файл, лежащий прямо в папке категории (не в папке проекта), становится отдельным проектом с названием из имени файла.
Порядок работ внутри проекта — по именам файлов (натуральная сортировка: `2.jpg` раньше `10.jpg`). Хотите другой порядок — переименуйте файлы.

Исходники в `media-src/` скрипт только читает: ничего не переименовывает и не удаляет.

## Названия, кредиты, порядок, скрытие — `content/meta.json`

Открывайте в любом текстовом редакторе. Для каждого проекта:

```json
"styling/For Harry Denims": {
  "title": "For Harry Denims",   // название на сайте (здесь правятся опечатки)
  "credits": "ph: …, muah: …",   // кредиты; пусто — строка не показывается
  "year": "2026",                // год съёмки: показывается серым рядом с названием; пусто — не показывается
  "link": "https://instagram.com/…", // ссылка бренда или человека: название съёмки станет ссылкой; пусто — просто текст
  "order": null,                 // 1, 2, 3… — проект стоит первым/вторым/…; null — перемешивается при каждом заходе
  "railCount": null,             // из скольких первых работ проекта выбираются кадры для ленты; null — railPerProject из site.json
  "hide": false                  // true — убрать всю съёмку с сайта (исходники в media-src остаются)
}
```

Для каждой работы:

```json
"styling/For Harry Denims/IMG_3545.JPG": {
  "caption": "",        // подпись (показывается во вьюере)
  "hide": false,        // true — убрать работу с сайта (файл в media-src остаётся)
  "teaserStart": 0,     // только для видео: с какой секунды начинается 12-секундный тизер на рейле
  "role": ""            // "model" — Мила в кадре, "styling" — её стайлинг на других; пусто — по категории (site.json → roles)
}
```

Кнопки `model` / `styling` сверху фильтруют ленту, gallery и съёмки. Повторное нажатие возвращает всё. Прямые ссылки: `…/#/model`, `…/#/styling`.

После правок — `npm run media` и залить `docs/`.

Ссылка на съёмку: `…/#/p/<slug>` (slug виден в адресе, когда съёмка открыта). Ссылка на конкретную работу: адрес вида `…/#/look/<id>` в адресной строке, когда она открыта во вьюере. Эти адреса не меняются при переименовании файлов и перестановке порядка.

Если у съёмки заполнен `link`, её название в съёмке и во вьюере ведёт на эту страницу (инстаграм бренда, клип).

## Иконка и превью ссылки

Файл `content/brand/seal.png` — картинка, из которой `npm run media` делает `favicon.png`, иконку для iPhone и `og.jpg` для превью ссылки в мессенджерах. Чтобы заменить, положите новый файл с тем же именем и запустите `npm run media`. На самом сайте этого знака нет.

## Контакты, подписи, категории, режим рейла — `content/site.json`

| поле | что это |
|---|---|
| `name`, `role`, `city` | имя, роль, город (показываются в contact и в `<title>`) |
| `description` | описание для поисковиков и превью в мессенджерах |
| `url` | адрес сайта, например `https://milaharys.com` — нужен для корректного превью (og:image) при отправке ссылки |
| `instagram`, `email`, `telegram` | контакты; `TODO` или пустая строка — ссылка не показывается |
| `labels.gallery`, `labels.contact`, `labels.model`, `labels.styling` | подписи кнопок в навигации (`gallery`, `contact`, `modeling`, `styling`) |
| `roles` | к какой кнопке относится категория по умолчанию: `"model"` или `"styling"` (отдельный кадр переназначается полем `role` в `meta.json`) |
| `categories` | отображаемые названия категорий по имени папки |
| `railMode` | `"projects"` — кадры одной съёмки идут подряд; `"mix"` — все кадры ленты вперемешку |
| `railPerProject` | из скольких первых работ проекта выбираются кадры для ленты (по умолчанию 6) |
| `stripMin`, `stripMax` | сколько кадров каждой съёмки показывать в ленте при каждом заходе (случайно от 3 до 4) |

После правок — `npm run media` (мета-теги и контакты встраиваются в `docs/index.html`).

## Что где лежит

```
media-src/        исходники (только читаются)
content/          site.json, meta.json — то, что правит человек
tools/            build-media.mjs — медиа-пайплайн
docs/           ← это заливается на хостинг
  media/rail      лёгкие версии (высота 1200px, тизеры видео 12 с без звука) — показываются первыми
  media/full      HQ (2560px, видео целиком со звуком) — подгружаются поверх, когда экран крупный
  media/poster    постеры видео
  data/manifest.json  список всех проектов и работ (генерируется)
```

## Если что-то не так

- `npm run media` ругается на бюджет — это предупреждение, а не ошибка: файл просто тяжелее ожидаемого. Сайт работает.
- Исходник меньше 1600px по длинной стороне — в отчёте строка «sources below 1600px»: в HQ такое фото будет мягким. Лучше заменить на оригинал побольше.
- Фото стоит боком — перезапустите `npm run media`; ориентация берётся из EXIF. Если и в исходнике боком, поверните файл в «Просмотре» на Mac и сохраните.
